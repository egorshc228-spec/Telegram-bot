# Демо AI-бота для бизнеса (Telegram + Claude)

Витрина для показа клиентам. Человек открывает бота, выбирает компанию (салон, автосервис, магазин,
стоматология) и сам пробует: цены, график, частые вопросы, запись кнопками, диалог с AI-администратором
своими словами, фото, затем смотрит глазами владельца: заявка с кнопками «Подтвердить / Связаться»
и Excel-отчёт. Все компании вымышленные.

## Запуск на Railway (та же схема, что у первого бота)

1. В BotFather создайте **нового** бота для демо (`/newbot`). Токен одного бота нельзя запускать в двух местах.
2. На GitHub создайте новый приватный репозиторий и загрузите **содержимое** этой папки (распакуйте zip!),
   чтобы `Dockerfile` лежал в корне репозитория.
3. Railway: New Project → Deploy from GitHub repo → этот репозиторий.
4. Variables: `TELEGRAM_BOT_TOKEN`, `ANTHROPIC_API_KEY`, `OWNER_ID` (ваш ID у @userinfobot).
   Необязательно: `CLAUDE_MODEL`, `USER_DAILY_LIMIT`, `GLOBAL_DAILY_LIMIT`.
5. Volume с путём `/srv/data` (иначе заявки стираются при обновлении).
6. В логах должна появиться строка `Start polling`. Напишите боту `/start`.

Файл `.env` на GitHub не загружайте.

## Что видите вы как владелец

- Каждая демо-заявка и каждая просьба «Хочу такого бота» приходят вам в Telegram.
- `/stats` — пользователи, заявки, расход ИИ-сообщений за сегодня. `/leads` — Excel со всеми заявками.

## Защита баланса

Сообщения ИИ (текст и фото) ограничены: `USER_DAILY_LIMIT` на человека и `GLOBAL_DAILY_LIMIT` на всех в сутки.
Кнопки без ИИ работают без лимита и бесплатно. Модель по умолчанию Haiku (самая дешёвая).


## Подключение CRM и онлайн-записи (реальное расписание)

Без настроек бот использует демо-расписание. Для реального клиента расписание берётся из его системы:
бот видит свободные окна, а заявка создаёт запись прямо в CRM (если слот занят, клиент увидит это сразу,
и ИИ предложит другое время).

| Система | Статус | Что нужно |
|---|---|---|
| **Altegio** (бывший YCLIENTS) | готовый адаптер по официальному API (`book_times`, `book_record`) | partner token (developer.alteg.io), ID филиала (`location_id`), ID услуг, отключённое SMS-подтверждение телефона |
| **CleverBox** | универсальный адаптер, нужна их документация | у публичного сайта CleverBox описания API я не нашёл: запросите у поддержки доступ к API, адреса методов и ключ, затем впишите их в `booking.json` |
| **Другая CRM** (любая с REST API) | универсальный адаптер `generic` | документация API: метод получения свободного времени и метод создания записи |

**Как подключить**
1. Скопируйте `booking.example.json` в `booking.json` (или положите весь JSON одной строкой в переменную `BOOKING_CONFIG` на Railway).
2. Для нужной компании (ключ `salon`, `auto`, `shop`, `dental` или ваш) укажите `provider`: `altegio` или `generic`.
3. Ключи в JSON не пишите. Пишите `env:ИМЯ_ПЕРЕМЕННОЙ` и добавьте переменную в Railway Variables (например `ALTEGIO_PARTNER_TOKEN`).
4. В таблице `services` сопоставьте названия услуг из `app/niches.py` с ID услуг в CRM. Услуги без ID бот не запишет и предупредит об этом в логах при старте.
5. Перезапустите. В логах: `Расписание: salon: Altegio, ...`.

Как это работает: перед показом дней и времени бот запрашивает слоты (кэш 45 секунд, чтобы не упереться в лимит API),
перед записью проверяет слот ещё раз, затем создаёт запись. Номер записи в CRM виден в карточке заявки и в Excel.
Если CRM недоступна, бот не выдумывает время: честно говорит, что расписание недоступно.
Телефон приводится к формату `+380...` (код страны меняется в `country_code`).

**Общий адаптер `generic`** настраивается без кода: адрес API, заголовки, метод и путь запроса слотов, где в ответе
лежит список (`result_path`, например `data.slots`), поле времени, тело запроса на создание записи с подстановками
`{date} {time} {service_id} {staff_id} {name} {phone} {comment}`. Пример в `booking.example.json`.

Ограничения: подтверждение заявки владельцем кнопкой пока не меняет статус записи в CRM (запись в CRM создаётся сразу при заявке);
если филиал Altegio требует SMS-код для онлайн-записи, запись без кода не пройдёт; настройки реальной CRM проверяйте на тестовом
филиале до показа клиенту.

## Как сделать бота под реального клиента

Откройте `app/niches.py`, скопируйте любой блок, подставьте название, прайс, график, адрес, FAQ, окна записи.
Для живого клиента нужно ещё заменить «выдуманную занятость» (`free_slots`) на его реальное расписание.

## Структура

```
app/main.py     запуск
app/bot.py      меню, запись кнопками, роль владельца, Excel, ИИ-режим
app/ai.py       Claude: ответы по данным компании, анализ фото, инструмент create_lead
app/niches.py   данные 4 компаний
app/booking/    расписание: demo, altegio, generic (любая CRM по REST)
app/db.py       заявки, лимиты (SQLite)
app/report.py   Excel-отчёт
tests/          python -m tests.test_demo ; tests.test_flow ; tests.test_booking
```

## Ограничения

- Состояние диалогов в памяти: после перезапуска бота диалоги и начатые записи сбрасываются (заявки сохраняются).
- Свободное время в демо условное, реальной синхронизации с календарём нет.
- ИИ может ошибаться: в промпте стоит «только по данным», но для боевого клиента проверяйте диалоги.
