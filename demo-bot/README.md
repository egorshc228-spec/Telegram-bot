# AI-администратор для бизнеса в Telegram (Claude)

Бот без кнопок: клиент пишет обычным текстом или присылает фото, Claude понимает, что нужно, и действует:
называет цены, показывает свободное время, записывает, смотрит фото, показывает записи, принимает отзывы.
Если не может помочь, передаёт вопрос владельцу. Все компании в демо вымышленные.

## Что умеет

| Возможность | Как клиент этим пользуется |
|---|---|
| Ответы по прайсу, графику, FAQ | просто пишет вопрос |
| Запись | «запишите на стрижку в субботу вечером». Имя и телефон спрашиваются один раз, дальше берутся из профиля |
| Анализ фото | присылает фото (с подписью или без), бот понимает, чего он хочет |
| **Личный кабинет** `/cabinet` | календарь месяца с отмеченными днями записей, ближайшие записи со статусом, история визитов и сумма, прогресс до скидки, подсказка оценить визит |
| **Профиль** `/profile` | изменить имя и телефон: словами («изменить имя на Анна») или `/name`, `/phone` |
| Перенос и отмена | «отмени запись №5», «перенесите на пятницу» |
| **Отзывы** `/review` | оценка 1–5 и текст, либо словами («поставлю 5, всё понравилось»). Владельцу приходит уведомление, низкая оценка помечается |
| **Вызов владельца** | если ответа нет в данных, жалоба, просьба человека, запись не получается, ИИ недоступен или лимит исчерпан. Клиенту: «сейчас уточню у владельца», владельцу: карточка с контекстом и кнопка «Ответить клиенту» |

Непонятное сообщение: бот отвечает «Не смог разобрать, что вам нужно 🤔 Напишите, например…».
Основные фразы клиента и реакции на них заданы в `app/rules.py`: меняйте их там.

## Режимы

- `DEMO_MODE=1` (по умолчанию): демонстрация. Компании переключаются командами `/salon /auto /shop /dental`,
  доступны `/owner` (заявка глазами владельца), `/report` (Excel), `/how`, а фраза «хочу такого бота» уходит вам.
- `DEMO_MODE=0`: рабочий режим для клиента. Одна компания (`DEFAULT_NICHE`), без демо-команд.

## Команды

Клиент: `/start` `/cabinet` `/profile` `/name` `/phone` `/review` `/cancel`.
Владелец (ваш `OWNER_ID`): `/stats` `/leads` (Excel всех записей) `/reviews`, кнопки ✅ ❌ ✉️ в карточках.

## Переменные Railway

| Переменная | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота из BotFather |
| `ANTHROPIC_API_KEY` | ключ Claude API (без него бот передаёт все вопросы владельцу) |
| `OWNER_ID` | ваш Telegram ID, сюда приходят заявки, отзывы и вызовы |
| `DEFAULT_NICHE` | компания по умолчанию: `salon`, `auto`, `shop`, `dental` |
| `DEMO_MODE` | `1` демо, `0` рабочий режим |
| `USER_DAILY_LIMIT` / `GLOBAL_DAILY_LIMIT` | лимиты ИИ-сообщений на человека и всего в сутки (15 и 300) |
| `DEFAULT_LANG` | язык, пока клиент не выбрал свой: `ru`, `uk` или `en` (по умолчанию `ru`) |
| `REMINDERS` | `1` напоминания за сутки и за 2 часа до визита, `0` выключить |
| `REMINDER_CHECK_SECONDS` | как часто проверять, пора ли напомнить (по умолчанию 300) |
| `LOYALTY_EVERY` / `LOYALTY_DISCOUNT` | скидка каждый N-й визит в кабинете (5 и 10, `0` отключает) |
| `CLAUDE_MODEL` | модель (по умолчанию Haiku, самая дешёвая) |

Новые переменные необязательны: бот работает и без них.

## Запуск на Railway

1. Бот в BotFather, ключ Claude, свой ID у @userinfobot.
2. Репозиторий на GitHub: содержимое этой папки, `Dockerfile` в корне.
3. Railway: Deploy from GitHub repo → Variables → Volume `/srv/data`.
4. В логах `Start polling`, затем напишите боту.

Обновление кода: замените файлы на GitHub, Railway пересоберёт бота сам. База (заявки, профили, отзывы)
хранится в Volume и при обновлении сохраняется, новые таблицы и колонки добавляются автоматически.

## Подключение CRM и онлайн-записи (реальное расписание)

Без настроек бот использует демо-расписание. Для реального клиента расписание берётся из его системы:
бот видит свободные окна, а заявка создаёт запись прямо в CRM (если слот занят, клиент увидит это сразу,
и ИИ предложит другое время).

| Система | Статус | Что нужно |
|---|---|---|
| **Altegio** (бывший YCLIENTS) | готовый адаптер по официальному API (`book_times`, `book_record`) | partner token (developer.alteg.io), ID филиала (`location_id`), ID услуг, отключённое SMS-подтверждение телефона |
| **CleverBox** | универсальный адаптер, нужна их документация | у публичного сайта CleverBox описания API я не нашёл: запросите у поддержки доступ к API, адреса методов и ключ, затем впишите их в `booking.json` |
| **Другая CRM** (любая с REST API) | универсальный адаптер `generic` | документация API: метод получения свободного времени и метод создания записи |

**Как подключить**
1. Скопируйте `booking.example.json` в `booking.json` (или положите весь JSON одной строкой в переменную `BOOKING_CONFIG` на Railway).
2. Для нужной компании (ключ `salon`, `auto`, `shop`, `dental` или ваш) укажите `provider`: `altegio` или `generic`.
3. Ключи в JSON не пишите. Пишите `env:ИМЯ_ПЕРЕМЕННОЙ` и добавьте переменную в Railway Variables (например `ALTEGIO_PARTNER_TOKEN`).
4. В таблице `services` сопоставьте названия услуг из `app/niches.py` с ID услуг в CRM. Услуги без ID бот не запишет и предупредит об этом в логах при старте.
5. Перезапустите. В логах: `Расписание: salon: Altegio, ...`.

Как это работает: перед показом дней и времени бот запрашивает слоты (кэш 45 секунд, чтобы не упереться в лимит API),
перед записью проверяет слот ещё раз, затем создаёт запись. Номер записи в CRM виден в карточке заявки и в Excel.
Если CRM недоступна, бот не выдумывает время: честно говорит, что расписание недоступно.
Телефон приводится к формату `+380...` (код страны меняется в `country_code`).

**Общий адаптер `generic`** настраивается без кода: адрес API, заголовки, метод и путь запроса слотов, где в ответе
лежит список (`result_path`, например `data.slots`), поле времени, тело запроса на создание записи с подстановками
`{date} {time} {service_id} {staff_id} {name} {phone} {comment}`. Пример в `booking.example.json`.

Ограничения: подтверждение заявки владельцем кнопкой пока не меняет статус записи в CRM (запись в CRM создаётся сразу при заявке);
если филиал Altegio требует SMS-код для онлайн-записи, запись без кода не пройдёт; настройки реальной CRM проверяйте на тестовом
филиале до показа клиенту.

## Воронка ADrenaline (демо для владельцев бизнеса с сайта)

Включается сама при `DEMO_MODE=1` (выключить: `FUNNEL=0`). Человек с сайта — владелец бизнеса, а не клиент салона,
поэтому поверх демо работает слой продаж ADrenaline:

1. `/start <метка>` с сайта: без экрана языка (язык из Telegram, иначе украинский), сразу вопрос «Яка у вас сфера?» →
   салон / клиника / автосервис / магазин / «другое» (бот подбирает ближайший пример и запоминает текст).
2. Роль клиента: короткое объяснение и клавиатура с 3 примерами фраз + «👀 Очима власника» + «📅 Дзвінок з ADrenaline».
3. После записи в демо — подсказка «посмотрите, что получил владелец»; если за 3 сообщения не записался — мягкая подсказка.
4. «Глазами владельца»: его собственная заявка с кнопками ✅/❌, что происходит дальше, Excel и напоминание.
5. Мини-презентация из 6 экранов (одно сообщение, листается кнопками): потери со ссылками на исследования, что делает бот,
   калькулятор потерь в 2 клика, реальный кейс, цена, следующий шаг. На каждом экране кнопка записи.
6. Запись на звонок прямо в боте: 1–2 вопроса (обращений в день, кто сейчас отвечает) → день → время → Telegram / Meet / телефон.
   Даниилу (`SALES_CHAT_ID`) приходит карточка: кто, сфера, объём, чек, расчёт калькулятора, источник, что делал в демо;
   кнопки «Подтвердить», «Другое время», «Написать через бота». Посетитель получает напоминание за 2 часа, может перенести/отменить.
7. Не записался — до 4 фоллоу-апов (30 мин, 1, 3, 7 дней от последней активности, только 10:00–20:00 по Киеву),
   у каждого «Не цікаво». Записавшимся и отписавшимся не пишем; заблокировавших помечаем.
8. Если в демо человек пишет «хочу такого бота» / «сколько стоит» — ИИ отвечает ориентиром ($800 + $120/мес), бот показывает
   кнопку записи, Даниилу уходит «горячая» карточка.

Команды: `/call` — записаться на звонок; `/funnel [дни]` — воронка по шагам и источникам (OWNER_ID, SALES_STAFF_IDS или в группе «Заявки»).

**Группа «Заявки».** Создайте группу в Telegram, добавьте туда бота и сделайте его админом, узнайте ID группы (в web.telegram.org/a он в адресе после #, например -1001234567890) и впишите его в `SALES_CHAT_ID`. Карточки, напоминания и «хочет такого бота» пойдут в группу; кнопки может нажимать любой участник; «Написать через бота» — ответом на сообщение бота. ИИ в группе не отвечает.

**Метка с сайта.** Ссылка `t.me/CladchatBot?start=<источник>_<ga-client-id через дефис>`, например `ai_123456789-1700000000`
(`ai` = /ai-admin, `home` = главная, `ads` = /google-ads). Сайт подставляет её сам при клике. Если в Railway Variables задан
`GA4_API_SECRET` (секрет «demo-bot», в git не хранится), события бота (`bot_start`, `demo_niche`, `demo_booking`, `owner_view`, `pitch_view`,
`calc_done`, `slots_view`, `call_booked`, `want_bot`, `followup_sent`, `opt_out`) уходят в GA4 к тому же посетителю, что и клик.

**Файлы:** `app/funnel.py` (роутер воронки, подключается ПЕРЕД основным), `app/funnel_texts.py` (все тексты, uk/ru),
`app/sales.py` (таблицы `prospects` и `calls`, окна для звонков, расписание фоллоу-апов), `app/analytics.py` (GA4),
`tests/test_funnel.py` (полный прогон). Правки в старых файлах: `bot.py` (флаги `lead_id`/`want_bot` в ClientActions и вызов
`funnel.after_ai` после ответа ИИ), `ai.py` + `rules.py` (`RULES_FUNNEL`), `main.py` (роутер и фоновый цикл), `i18n.py` (команда /call).
Тексты меняйте только в `funnel_texts.py`; цифры там те же, что на сайте, с источниками.

## Структура

```
app/main.py      запуск, меню команд
app/bot.py       Telegram: свободный текст и фото, кабинет, отзывы, кнопки владельца, передача владельцу
app/ai.py        Claude: промпт и 6 инструментов (запись, кабинет, профиль, отмена, отзыв, вызов владельца)
app/rules.py     правила общения и типичные фразы клиентов
app/cabinet.py   личный кабинет и календарь
app/niches.py    данные компаний (прайс, график, FAQ)
app/booking/     расписание: demo, altegio, generic (любая CRM по REST)
app/db.py        записи, профили, отзывы, лимиты (SQLite)
app/report.py    Excel-отчёт
tests/           python -m tests.test_demo ; tests.test_flow ; tests.test_booking ; tests.test_funnel
```

## Ограничения

- Состояние диалога хранится в памяти: после перезапуска бот забывает контекст разговора (записи, профили и отзывы сохраняются).
- В демо часть свободных окон «занята» по формуле. Реальное расписание даёт подключённая CRM.
- Переписка клиента с владельцем идёт через бота: ответ владельца приходит клиенту сообщением от бота.
- Голосовые сообщения не распознаются (бот просит написать текстом или прислать фото).
- ИИ может ошибаться: цены и записи берутся только из данных компании, а владелец подтверждает записи кнопкой.

## Языки и напоминания

- Клиент выбирает язык при первом `/start` (русский, украинский, английский), потом меняет командой `/language`
  или просто просит в чате («switch to English»). Язык хранится в базе; пока не выбран, берётся язык Telegram.
- Все тексты клиента лежат в `app/i18n.py` (ключи `TEXTS`), переводы данных компаний в `NICHE_TR`.
  Владельцу всё приходит на русском. В базе и CRM услуга всегда хранится под русским названием.
- Напоминания (`app/reminders.py`): за сутки и за 2 часа до визита, на языке клиента. Если запись сделана
  впритык, лишнее напоминание пропускается. Отменённым и отклонённым записям не шлём. В демо: `/reminder`.
- Тесты: `python -m tests.test_demo`, `python -m tests.test_i18n`, `python -m tests.test_flow`, `python -m tests.test_booking`.
